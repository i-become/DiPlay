Usage: superdesign import-design-draft [options]

Import HTML you authored with your own model as a design draft (no AI generation, no credits).

The HTML must follow the platform draft contract:
  - ONE complete document per draft: <!DOCTYPE html> ... </html> (fragments are rejected)
  - Page and graphic drafts contain one screen; presentation drafts contain the approved slides
  - Tailwind utility classes for styling (CDN auto-injected if missing)
  - Icons via <iconify-icon> WITH its CDN script in <head> (not auto-injected)
  - <body> has NO class; all layout lives on a single root <div> child
  - Every <a> has a unique descriptive id; anchors never nest
  - Links: full https:// URLs or hash placeholders (#settings), never relative paths
Violations that would break rendering are rejected with fix guidance; lesser
issues are stored and returned as warnings[] for you to fix and re-import.

Usage Examples:
  superdesign import-design-draft --project-id <id> --title "Landing" --device desktop --html-file ./landing.html --generated-by <your-model-id>
  superdesign import-design-draft --project-id <id> --title "Quarterly Review" --device desktop --kind presentation --outline-file ./slides.json --html-file ./deck.html --generated-by <your-model-id>
  superdesign import-design-draft --into <draftId> --html-file ./landing-v2.html --generated-by <your-model-id>

Options:
  --html-file <path>                 Path to the HTML file authored by your own
                                     model
  --project-id <id>                  Project ID (required when creating a new
                                     draft)
  --title <title>                    Draft title (required when creating a new
                                     draft)
  --into <draftId>                   Push the HTML as a new version of this
                                     existing draft instead of creating a new
                                     one (revertible; viewport is fixed by the
                                     draft)
  --device <mode>                    Viewport preset the HTML was designed for
                                     (mobile, tablet, desktop) - or pass
                                     --width/--height instead
  --width <pixels>                   Custom viewport width (20-10000, with
                                     --height)
  --height <pixels>                  Custom viewport height (20-10000, with
                                     --width)
  --kind <kind>                      Artifact kind: page (default), graphic, or
                                     presentation
  --summary <text>                   Presentation purpose, audience, and
                                     narrative summary
  --outline-file <path>              JSON file containing the complete approved
                                     presentation slides
  --slides-json <json>               Inline JSON containing the complete
                                     approved presentation slides
  --navigation-controls <show|hide>  Presentation on-screen navigation
                                     preference
  --transition <effect>              Presentation transition: auto, none, fade,
                                     slide, push, zoom, reveal, or custom
  --custom-transition <text>         Custom transition direction; required with
                                     --transition custom
  --brand-assets <use|ignore>        Presentation Project Brand Assets
                                     preference
  --generated-by <model>             Id of YOUR model that authored the HTML
                                     (e.g. claude-fable-5); recorded as the
                                     draft's generation model
  --user-request <text>              Share the user's verbatim request with
                                     SuperDesign to improve quality evaluation;
                                     optional
  --json                             Output in JSON format
  -h, --help                         display help for command
