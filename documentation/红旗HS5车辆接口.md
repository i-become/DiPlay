# 红旗 HS5 车辆接口

本文记录 DiPlay 与红旗 HS5 启思车机的接口边界，便于维护和适配。接口来自应用源码中的调用实现，不是车厂正式发布的 SDK 规范。事务编号与数据解释针对项目测试使用的 HS5 车机固件；不同年款或固件可能不同。未在实车确认的字段标为“待验证”，不要据此控制车辆。

## 适用范围

- 目标环境：红旗 HS5 安卓车机及其启思（QiSi）适配服务。
- 车机车辆状态权限：`ltd.qisi.adapterservice.permission.READ_SETTINGS`。
- 可选方向盘与飞屏控制依赖系统服务及应用已获得的相应车机权限。
- 某个服务、管理器或事务不可用时，应用应保留手机互联主流程，并将可选数据视为未知。
- 车辆数据仅供仪表展示和诊断，不能替代原车仪表、告警或驾驶辅助系统。

## 车辆状态服务

车辆适配服务组件：

| 项目 | 值 |
| --- | --- |
| 服务包名 | `ltd.qisi.adapterservice` |
| 服务组件 | `ltd.qisi.adapterservice.QISIAdapterService` |
| 根接口 | `ltd.qisi.adapterproxy.IVehicleRemoteClienter` |
| 查询管理器 | 根接口事务 `1`，参数为管理器编号 |
| 车辆状态管理器 | 编号 `15`，接口 `ltd.qisi.adapterproxy.ICarVehicleStateManager` |
| 权限 | `ltd.qisi.adapterservice.permission.READ_SETTINGS` |

应用绑定服务后先检查 Binder 接口描述符，再查询车辆状态管理器。监听事务为 `42`（注册）和 `43`（取消）；回调描述符为 `ltd.qisi.adapterproxy.listener.IVehicleCarStateChangedListener`。关闭采集或 Binder 断开时取消监听并清空本地缓存；重连采用退避/延时策略。

### 常用数据

| 项目 | 读取事务 / 推送事务 | 参数 | 应用解释 |
| --- | --- | --- | --- |
| 车速 | 读取 `7` / 推送 `10` | 无 | 原始值除以 100 得到 km/h；只接受 0–26000 |
| 挡位 | 读取 `6` / 推送 `11` | 无 | `0=P, 1=R, 2=N, 3=D, 4=S, 5=M, 6=W, 7=E, 8=B` |
| 油量 | 读取 `31` / 推送 `30` | 无 | 0–100，按百分比换算 |
| 低油量提示 | 读取 `58` / 推送 `29` | 无 | 忽略 `254/255`；其余非零视为提示有效 |
| 剩余里程 | 读取 `2` / 推送 `31` | 无 | 0–1022，按公里处理；推送优先 |
| 胎压 | 读取 `26` / 单轮推送 `47` | 读取参数为车轮序号 0–3；推送为车轮序号及数值 | 回调/读取值为 kPa，除以 100 显示 bar；接受 1–700。无效推送保留上一有效值 |
| 胎压告警 | 读取 `80` / 单轮推送 `49` | 同上 | 仅 `0/1` 有效；48 号系统通知触发四轮重新读取 |
| 安全带 | 读取 `4` | 参数 0 / 1 | 分别对应驾驶员 / 副驾驶座；当前仅驾驶员状态进入告警模型 |
| 制动状态 | 读取 `11` | 无 | 原始状态；不能据此推断电子驻车状态 |
| 平均油耗 | 读取 `25` | 无 | 目标固件直接返回显示单位；需开启行驶信息采集 |
| 总里程 | 读取 `24` | 无 | 目标固件直接返回公里显示值；需开启行驶信息采集 |

胎压、告警和安全带等字段的接口返回值可能因固件差异而变化。数据缺失或无效时应显示未知，不应把它当成正常或故障结论。

### 更新和缓存

车辆状态监听是主要更新来源；初次绑定会先注册监听再读取初始值。速度或挡位推送会触发行驶信息读取及胎压刷新。胎压读取至少间隔约 1 秒；轮胎数据缺失时会重试。转速每 750 毫秒通过车机 RPC 数据读取。普通非推送字段的缓存有效期为 2.5 秒；推送通道连接期间，部分状态保留最近一次有效推送，直到断连清空。

诊断页面可查看服务连接状态、原始读数、数据年龄和拒绝原因。诊断日志受应用诊断开关控制；发布报告前应检查设备和连接信息。

## 车机 CAN / RPC 数据

对车机框架中的 `alfusos.rpc.RpcManager` 使用反射，以避免将车厂框架类打入 APK。通过 `getMessage(1872, byte[26])` 读取数据，消息编号放入请求首字节。

| 消息 | 用途 | 当前处理 |
| --- | --- | --- |
| `0` | EMS_3 发动机数据 | 优先使用随车 HS5 接口语义解析；后备按字节 1–2 小端值乘 0.25 计算转速 |
| `24` | 冷却液数据 | 已校验帧号和长度；温度字节按摄氏度解释 |
| `55`、`6` | IFC 驾驶辅助帧 | 提取前车与左右车道检测位，仅供可选仪表显示 |

RPM 在 P 挡、车速接近零且读数不高于 350 时隐藏。错误、缺帧、未知固件类或 RPC 不可用时返回未知，不影响主连接流程。上述帧布局并非车厂公开承诺的稳定 ABI。

## 可选车辆管理器

扩展管理器单独查询，失败不影响基础车辆状态：

| 管理器 | 编号 | 接口 | 使用 |
| --- | ---: | --- | --- |
| 空调（ATC） | 33 | `ltd.qisi.adapterproxy.ICarATCManager` | 外部温度 getter 93，返回摄氏度浮点值 |
| 车身控制（BCM） | 25 | `ltd.qisi.adapterproxy.ICarBCMManager` | 可选车灯信息；以实际 getter 与固件能力为准 |
| 驾驶监测（DMS） | 18 | `ltd.qisi.adapterproxy.ICarDMSManager` | 当前仅探测管理器可用性 |
| 智能前视（IFC） | 46 | `ltd.qisi.adapterproxy.ICarIFCManager` | 辅助状态推送；数据仍需有效性校验 |
| 抬头显示（HUD） | 23 | `ltd.qisi.adapterproxy.ICarHUDManager` | HUD / ADAS 状态推送 |

HUD 和 IFC 使用各自的回调接口，并在车辆监视停止时取消订阅。枚举值是固件原始状态，不应在未验证映射时作跨固件解释。未列入应用映射的信号只记录可用性，不展示为确定的车辆事实。

## 方向盘按键与画面焦点

系统服务组件为 `ltd.qisi.systemservice/.QisiSystemService`，接口为 `ltd.qisi.systemmanager.ISystemServiceInterface`。

| 操作 | 事务 / 值 | 用途 |
| --- | --- | --- |
| 注册系统回调 | `3`；取消为 `4` | 接收车机系统事件 |
| 注册 / 取消方向盘按键 | `12` / `13` | 提交包名、按键码数组和回调 Binder |
| 发送车机命令 | `1` | 按协议发送方向盘/语音等车机命令 |


应用按需登记，结束会话或关闭飞屏后释放按键与焦点。注册失败时不应阻止常规手机互联。

仪表地图开启时，上一曲长按（动作 `1`）打开飞屏，重复事件只触发一次，动作 `2` 释放后可再次触发；不依赖三指手势开关。短按仍切换上一曲，使用原车蓝牙音频或未启用媒体接管时通过 Android 媒体按键接口交给当前媒体会话。关闭仪表地图后不再启用此长按入口。新增入口及原车蓝牙短按转发尚需实车验证。

## 仪表导航输出与飞屏

启思车辆输出服务仍由 `QISIAdapterService` 提供，根 Binder 查询事务为 `1`。导航与仪表输出涉及 HUD（模块 23）、仪表相关模块（编号 8）和系统控制模块（编号 13）。接口分别为：

- `ltd.qisi.adapterproxy.ICarHUDManager`
- `ltd.qisi.adapterproxy.ICarInstrumentRelatedManager`
- `ltd.qisi.adapterproxy.ICarSystemControlManager`

HUD 导航输出包括转向图标、环岛出口、路口距离、道路/车道类型、导航状态、目的地、剩余时间与总距离等；仪表导航帧通过事务 `6` 发送，仪表地图模式通过事务 `10` 设置。项目根据连接协议提供的导航数据构建这些输出；手机没有下发的数据无法从接口补齐。


全屏仪表导航期间，应用登记系统控制回调（事务 `64` 注册，`65` 取消），请求仪表地图模式 `4`，启用仪表导航显示；退出时恢复地图模式 `2` 并清除导航显示状态。车机回调中的 `HardKeyQuit` 或 `0` 请求退出当前仪表窗口。

## 示宽灯与熄屏

### 独立仪表的系统音乐（固件线索，未实车验证）

候选服务为 `ltd.qisi.datasyncservice/.DataSyncService`，候选 Provider 为 `content://ltd.qisi.datasync.datasyncProvider/domainValue_table`。依据维护者提供的 QisiMusicNavReaderKit 参考说明，匹配车机 SDK 提供 `QisiDataSyncManager`、`get/getValues/registerListener` 等读取订阅接口；但 SDK/AIDL 未随参考包提供，项目不猜 Binder 协议，也不调用未验证的反射入口。应用仅在独立仪表有订阅时通过标准 ContentResolver 尝试读取已知音乐字段及导航格式化字段；Provider 表结构与访问能力在运行时检查，失败不影响 CarPlay。导航字段清单、displayId 后缀及其限制见[独立仪表与中控区域复制](独立仪表与屏幕复制.md)。以上尚未在实车验证。

### 示宽灯与电源状态

示宽灯通过车辆状态管理器编号 `15`、读取事务 `19` 获取；`0` 为日间、`1` 为夜间，其余值视为未知。应用只在收到有效状态后切换自动主题。

熄屏和整车电源状态通过 `com.alfus.controller/.power.PowerController` 系统状态接口读取，并在状态变化时接收回调：

| 状态值 | 解释 |
| ---: | --- |
| 2、3、4 | 熄屏、关机或 ACC 关闭，按关闭状态处理 |
| 1、5、6、12 | 按屏幕/系统可用状态处理 |
| 其他 | 未知；不推断电源状态 |


## 权限、失败处理与排查

- 车机数据读取使用清单中的 QiSi 读取权限；系统服务是否允许应用绑定由固件策略决定。
- 车辆数据、方向盘、仪表输出、系统状态服务各自独立探测。Binder 描述符或事务不匹配时，该能力不可用，其他功能继续运行。
- 车机接口不是面向普通应用的公开 Android API；固件升级可能改变组件、事务或枚举值。
- 开启应用诊断后，可检查车辆服务绑定、管理器可用性、原始数据和状态年龄。关闭诊断时，不应持续写入诊断文件。
- 实车验证请在安全停放状态进行，不要通过注入车辆状态或发送未记录事务验证行驶控制功能。
