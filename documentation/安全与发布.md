# 敏感文件与发布说明

## 不得纳入公开仓库

- Android 签名密钥库、密钥口令与本地签名配置。
- 苹果认证证书、私钥及其容器文件。
- `runtime-assets/`、`.private/`、`offline-mfi/` 内的本地材料。
- `common/libs/`、`mobile/libs/`、`mobile/src/main/jniLibs/` 中的本地依赖与预编译库。
- 已嵌入认证材料的安装包，以及未经隐私检查的诊断报告。

忽略规则用于防止误添加，`scripts/check_public_tree.py` 检查当前 Git 跟踪文件。取消跟踪不会清除旧提交中的内容；公开已有仓库前，还应单独审查历史、标签与发布附件。已泄露的密钥应撤销或更换，不能依靠删除文件恢复保密性。

## 本地签名配置

签名读取以下环境变量，或本地 `local.properties` 中对应键：

| 环境变量 | 本地配置键 |
| --- | --- |
| `ANDROID_KEYSTORE_PATH` | `storeFile` |
| `ANDROID_KEYSTORE_PASSWORD` | `storePassword` |
| `ANDROID_KEY_ALIAS` | `keyAlias` |
| `ANDROID_KEY_PASSWORD` | `keyPassword` |

请在本地或持续集成的密钥管理中配置实际值，不要写入源码、示例文档或命令输出。发布签名与 CarPlay 认证身份是不同的材料，二次开发者应分别配置自己有权使用的材料。

Windows 维护者可在仓库根目录运行 `scripts/build-release.ps1`，并传入三段式版本号，例如 `powershell -ExecutionPolicy Bypass -File .\scripts\build-release.ps1 1.4.3`。脚本默认从仓库 `runtime-assets/` 读取 CarPlay 认证材料，也可通过 `DIPLAY_AUTH_ASSETS_DIR` 指向其他本地目录；它会构建 Release、检查包名/版本/签名/认证资产，并在 `dist/release-版本号/` 输出 APK 与 `SHA256SUMS.txt`。版本代码按“主版本 × 1000 + 次版本 × 100 + 补丁版本”计算，因此次版本号范围为 0–9、补丁版本号范围为 0–99。

## 应用内更新附件

正式更新的标签使用 `v1.4.4` 或 `1.4.4` 形式，APK 使用 `DiPlay-1.4.4.apk`（也接受 `DiPlay-v1.4.4.apk`）。同一发布只放一个对应版本的正式 APK，另附 `SHA256SUMS.txt`；调试包、其他版本附件和预发布不会作为正式更新。APK 内部版本名必须与标签一致，内部版本号不能低于已安装版本，包名和签名也须匹配。

**必须对最终签名、所有后处理完成后的 APK 生成校验值**。生成后不要再改动 APK；重新构建或签名后须同时替换 APK 和校验文件。PowerShell 示例（在最终 APK 所在目录执行）：

```powershell
$updateApk = Get-Item -LiteralPath '.\DiPlay-1.4.4.apk'
$updateHash = (Get-FileHash -LiteralPath $updateApk.FullName -Algorithm SHA256).Hash.ToLowerInvariant()
"$updateHash  $($updateApk.Name)" | Set-Content -LiteralPath '.\SHA256SUMS.txt' -Encoding UTF8
```

两份附件应发布到同一个版本，镜像同步时也必须一起同步。客户端会区分缺少校验条目与实际 SHA-256 不匹配，并在下载校验后检查 APK 内的包名、版本；不会通过跳过校验解决更新错误。GitCode 为主要更新源，接口失败时使用 GitHub 镜像；接口限流会显示检查失败，不能据此判断已安装最新版本。

## 认证与诊断

CarPlay 认证材料仅通过 `DIPLAY_AUTH_ASSETS_DIR` 显式导入。安装包内的认证材料可能被提取；应遵守材料所有者的使用和分发要求，项目兼容性描述不代表获得苹果认证。

公开诊断报告前，请检查设备名称、蓝牙地址、网络信息与配对记录。涉及私钥或安全缺陷时，请通过仓库提供的私密渠道报告，不要发布到公开问题区。
